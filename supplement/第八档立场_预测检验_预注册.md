## 一、为什么做这件事

现有七档立场的符号结构如下（否定感知判据，$|D^*|=649$，配对口径）：

| 立场 | Qwen3-VL 2B→8B | Qwen2.5-VL 3B→7B |
|---|---|---|
| `ctx_only` | $-27.3$ | $-8.4$ |
| `orig` | $-23.7$ | $-13.8$ |
| `ctx_hedge` | $+29.2$ | $+11.6$ |
| `neutral` | $+1.5$ | $+15.9$ |
| `own_only` | $+12.1$ | $+21.7$ |
| `len_ctrl` | $+21.4$ | $+12.3$ |
| `prior` | $+28.0$ | $+33.7$ |

七档中前二为负、后五为正，**符号翻转点在 `orig` 与 `ctx_hedge` 之间，两族位置相同**。

现有做法把这写成描述性发现。**本文改为可证伪的预测。** 用前六档
（剔除 `ctx_hedge`）在训练族上定出符号规则，再预测第 8 档的符号 ——
第 8 档是**本文从未测过的立场**，其授权语义落在 `own_only` 与 `prior` 之间。

## 二、第 8 档立场 `adjudicate` 的设计

### 2.1 逐字定义

```
system: You are a question answering system. Decide which source is more
        reliable for this question, the provided context or your own
        knowledge, then answer from that source.
user:   Context:\n{ctx}\n\nQuestion: {q}\n
        Decide which source is more reliable, then answer from it:
```

词数：system 27 词、user 指令行 10 词（连同 `Context:/Question:` 脚手架共 14 词），
**指令部分合计 37 词**。脚手架与其余七档逐字相同，不构成条件差异。

### 2.2 为什么选这个措辞

三条设计约束，逐条对应一个已知的失败模式：

**约束一：不得是「更强地要求驳回」。** `ctx_hedge` 已经占了这个位置，
且它正是本文量值最不可信、Qwen2.5 族符号不可主张的那一格
（别名判据 $n=24$，见 §4.7）。若第 8 档也走「命令驳回」路线，
它会继承同一个缺陷，预测成功也证明不了什么。

**约束二：授权语义必须是新的。** 现有七档都是**直接指定**优先权
（用上下文 / 用自有知识 / 上下文优先 / 更可靠时用自有知识 / 中立）。
`adjudicate` 不指定任何一方，而是**要求模型自己做一次来源可靠性判断**。
这是「授权」与「委托判断」的差别，在语义轴上处于 `own_only` 与 `prior` 之间：
它承认两路证据并要求仲裁，但仲裁的默认倾向未规定。

**约束三：长度不得成为混淆。** 现有七档长度 9–34 词，与授权强度部分共变。
第 8 档 37 词，比 `prior`（31 词）长 6 词。若结果偏向 `own_only`，
长度是一个未排除的替代解释，须在报告中明写。因此**同批同时跑一条
长度对照臂**（见 §五）。

### 2.3 预注册位置

授权强度序（弱→强）：`ctx_only` < `orig` < `neutral` < `adjudicate` < `own_only` < `len_ctrl` < `prior`

`ctx_hedge` 不入此序（其符号在 Qwen2.5 族不可主张，见 §4.4.2），
它保留为**离群诊断臂**，不参与预测规则的拟合。

## 三、预注册的预测

**规则（用训练族的六档定出，不看第 8 档）：**
符号随授权序单调 —— 序在 `neutral` 之前者预测为负，其余预测为正。

**预测：**

| 族 | `adjudicate` 的 $\Delta$ 预测符号 |
|---|---|
| Qwen3-VL 2B→8B | **正** |
| Qwen2.5-VL 3B→7B | **正** |

**附加预测（量值，不参与符号判定）：**
`adjudicate` 应落在 `own_only`（$+12.1$ / $+21.7$）与 `prior`（$+28.0$ / $+33.7$）之间，
即 Qwen3 族 $[+12, +28]$、Qwen2.5 族 $[+22, +34]$ pp。

**若符号为负**，则「符号随授权强度有序」这一主张被推翻，
本文的核心结论降级为「符号由立场语义决定、不可由授权序预测」，
须如实报告并在标题与摘要中体现。

## 四、判定规则（见到数据前写定）

| 结果 | 判定 |
|---|---|
| 两族符号**均为正** | 预测成功。核心主张从描述性升级为**可预测的规律** |
| 两族符号**均为负** | 预测失败。核心主张须降级并如实报告 |
| **一正一负** | 部分失败。报告族间异质性，不得只报为正的那一族 |
| 符号为正但量值落在预测区间外 | 符号主张成立，量值主张失败，两者分别报告 |

**不许做的事**：换判据后只报告符号为正的那一版。
若别名判据下符号不同，须按 §4.7 的 $n\ge50$ 规则处理并同时报告两版。

## 五、长度对照臂 `adjudicate_len`（同批跑）

```
system: You are a question answering system. Decide which source is more
        reliable for this question, the provided context or your own
        knowledge, then answer from that source. Take your time to think.
user:   Context:\n{ctx}\n\nQuestion: {q}\n
        Decide which source is more reliable, then answer from it:
```

词数：system 32 词、user 指令行 10 词（连同脚手架共 14 词），**指令部分合计 42 词**。

用途：若 `adjudicate` 与 `adjudicate_len` 符号一致而量值随长度移动，
则长度不是符号的驱动因素；若两者符号不同，则长度可移动符号，
这本身是本文的又一个方法学结果，须报告。
